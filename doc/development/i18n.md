# Internationalisation du frontend

Le plugin propose l’anglais et le français. À son chargement, il choisit la
première langue prise en charge dans `navigator.languages` (`fr-FR`, `fr-CA`,
`en-GB`… acceptés). Sans langue prise en charge, il utilise l’anglais. Recharger
Web Admin après un changement des préférences du navigateur. Le plugin suit le
thème clair/sombre choisi dans Web Admin.

## Ajouter un texte

Les catalogues sont `webadmin/src/i18n/locales/en.js` et `fr.js`. La clé est le
message anglais lisible. Importer `t` sous l’alias `tr`, puis traduire seulement
le texte d’interface :

```js
import { t as tr } from "../i18n/index.js";
tr("Inspect {p0}", { p0: "Patient.gender" });
```

Ajouter la même clé dans les deux catalogues. Les paramètres nommés sont
interpolés une seule fois : une expression ou une valeur contenant des accolades
reste intacte. Traduire chaque fragment humain d’un message composé. Les aides
contextuelles sont traduites au rendu, à partir des clés dans `host/help-texts.js`.
Les messages inconnus restent inchangés pour conserver un repli lisible.

Les noms de ressources, chemins FHIR, expressions, codes, URL, noms de contextes,
clés JSON, états techniques des traces et permissions OIE restent des données.
Les définitions des profils et diagnostics provenant du serveur conservent leur
langue d’origine. Les libellés du shell Web Admin dépendent du shell lui-même.
Aucun format d’étape ni résultat de compilation ne dépend de la langue.

## Contrôles

```sh
cd webadmin
npm run check
npm test
npm run test:e2e
E2E_BROWSER=webkit npm run test:e2e
```

`check` parse le JavaScript avec Acorn, contrôle les clés et paramètres des deux
catalogues et les appels de traduction à clé littérale. Il ne détecte pas tous
les textes oubliés ni les clés dynamiques : les aides, libellés composés et
nouveaux écrans demandent aussi une revue visuelle. Les tests unitaires vérifient
le choix de langue, le repli et l’invariance de la compilation. Les parcours
Playwright couvrent le français clair/sombre, le repli anglais, les éditeurs et
les réglages, ainsi que des refus HTTP 403 simulés. Un parcours RBAC séparé crée un compte
et un rôle temporaires, limite les canaux visibles et vérifie les 403 réels des
aperçus Profile Mapper/FML et de l’enregistrement des réglages. Il supprime le
compte et le rôle à la fin, y compris lors d’un échec. Ces tests demandent les
droits d’administration et le plugin RBAC de la démo.
